<threat_model>
## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| Admin browser → Backend API | JWT in localStorage, sent via fetch |
| WebSocket → Admin browser | Unidirectional broadcast, no sensitive data in payload |
| User input → Filters | Search query, status selection (XSS risk) |

## STRIDE Threat Register

| Threat ID | Category | Component | Disposition | Mitigation Plan |
|-----------|----------|-----------|-------------|-----------------|
| T-4-18 | Spoofing | Page access | mitigate | ProtectedRoute wrapper requires valid JWT. Unauthenticated users redirected to login. |
| T-4-19 | Tampering | Accept lead action | mitigate | Server-side verification in API endpoint. Client can't force acceptance without proper JWT. |
| T-4-20 | Information Disclosure | Lead data in DOM | accept | Leads displayed in admin dashboard (authenticated users only). No PII beyond what hipages provides. |
| T-4-21 | Tampering | XSS in search/filter | mitigate | React auto-escapes by default. No dangerouslySetInnerHTML. All user input rendered as text. |
| T-4-22 | Denial of Service | Excessive polling | mitigate | No polling - uses WebSocket push. Client can't trigger excessive API calls. |
| T-4-23 | Spoofing | WebSocket messages | accept | Read-only WebSocket (broadcast only). Client can't send commands via WebSocket. |
</threat_model>
