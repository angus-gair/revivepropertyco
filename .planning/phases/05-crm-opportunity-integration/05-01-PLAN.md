# Plan: CRM Opportunity API and Migration (05-01-PLAN.md)

This plan implements the backend changes, database schema modifications, and Twenty CRM integration helpers required to promote Hipages leads to CRM Opportunities.

## User Review Required

> [!IMPORTANT]
> A new database column `crm_opportunity_id` will be added to the `hipages_leads` table via migration `011`. This avoids breaking the foreign key constraint on `crm_lead_id` (which references local `leads`).

## Proposed Changes

### Database Migration
#### [M-1] Create Migration `011_add_crm_opportunity_id.sql`
- Add `crm_opportunity_id TEXT` to the `hipages_leads` table.
- Apply migration via `psql` in the database container and record it.

### Twenty CRM Integration
#### [T-1] Update `server/lib/twenty-client.cjs`
- Add helper method `findPersonByName(firstName, lastName)` using a GraphQL query.
- Add helper method `createOpportunity(opportunityData)` to create an Opportunity linked to a `Person`.

### API Endpoints
#### [A-1] Implement Promote Endpoint in `server/api/hipages.cjs`
- Implement `POST /api/hipages/leads/:id/promote-opportunity`.
- Check if lead is already promoted.
- Retrieve the workspace details (fallback to environment variables if no workspace is registered).
- Connect to Twenty CRM, match or create `Person`, and create `Opportunity`.
- Update `hipages_leads` set `synced_to_crm = true` and `crm_opportunity_id = <opportunityId>`.

## Verification Plan

### Automated Tests
- We will execute manual curl and postman tests against the promote API endpoint, stubbing out or connecting to the Twenty CRM container.

### Manual Verification
- Trigger the promote API for a test lead:
  ```bash
  curl -X POST http://localhost:8080/api/hipages/leads/<lead_id>/promote-opportunity \
    -H "Authorization: Bearer <admin_token>"
  ```
- Check that the lead is marked as synced in the local DB.
- Verify that the `Person` and `Opportunity` exist in the Twenty CRM database.
