<threat_model>
## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| hipages.com.au → Scraper | External website, untrusted input (HTML parsing) |
| Scraper → PostgreSQL | Direct database write, trusted service |
| Backend API → PostgreSQL | Parameterized queries, authenticated access |

## STRIDE Threat Register

| Threat ID | Category | Component | Disposition | Mitigation Plan |
|-----------|----------|-----------|-------------|-----------------|
| T-4-01 | Tampering | hipages_leads table | mitigate | Input validation at scraper (sanitize names, suburb), CHECK constraint on status, parameterized queries for all inserts |
| T-4-02 | Spoofing | hipages_id | accept | Hipages is source of truth, no authentication on their IDs. Unique constraint prevents duplicates. |
| T-4-03 | Information Disclosure | raw_data JSONB | accept | Contains full hipages response for audit. No PII beyond what hipages provides (customer names, suburbs, job descriptions). |
| T-4-04 | Denial of Service | Table size growth | mitigate | Index on scraped_at for efficient pruning. Document retention policy (90 days or after CRM sync). |
| T-4-05 | Tampering | crm_lead_id foreign key | mitigate | REFERENCES leads(id) ON DELETE SET NULL ensures integrity. If CRM lead deleted, hipages lead preserved. |
</threat_model>
