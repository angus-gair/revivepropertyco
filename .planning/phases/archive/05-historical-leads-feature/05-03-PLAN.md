### Task 1: Update Docker Configuration for Enhanced Scraper

**Type:** `auto`

**Files:** `services/hipages-scraper/Dockerfile`, `docker-compose.yml`

**Action:**
Update Docker configuration to support the enhanced scraper with longer runtime expectations.

1. **Update Dockerfile** to increase health check timeout (modify existing Dockerfile):
```dockerfile
# Add after the health check section (if exists, otherwise add at end)
HEALTHCHECK --interval=30s --timeout=30s --start-period=60s --retries=3 \
  CMD node -e "require('http').get('http://localhost:3000/health', (r) => {process.exit(r.statusCode === 200 ? 0 : 1)})" || exit 1

# Add environment variable for longer timeout
ENV SCRAPER_TIMEOUT=300000
ENV NODE_ENV=production
```

2. **Update docker-compose.yml** for hipages-scraper service:
```yaml
hipages-scraper:
  build:
    context: ./services/hipages-scraper
    dockerfile: Dockerfile
  image: hipages-scraper:latest
  container_name: hipages-scraper
  restart: unless-stopped
  environment:
    - DATABASE_URL=${DATABASE_URL}
    - HIPAGES_USERNAME=${HIPAGES_USERNAME}
    - HIPAGES_PASSWORD=${HIPAGES_PASSWORD}
    - HIPAGES_HEADLESS=true
    - CRON_SCHEDULE=0 */6 * * *
    - RUN_ON_STARTUP=false  # Don't run on startup after initial deployment
    - NODE_ENV=production
    - SCRAPER_TIMEOUT=300000  # 5 minutes
  volumes:
    - ./services/hipages-scraper/output:/app/output
  networks:
    - revive-network
  healthcheck:
    test: ["CMD", "node", "-e", "require('http').get('http://localhost:3000/health', (r) => {process.exit(r.statusCode === 200 ? 0 : 1)})"]
    interval: 30s
    timeout: 30s
    retries: 3
    start_period: 60s
  deploy:
    resources:
      limits:
        memory: 1G  # Increase memory limit for pagination
      reservations:
        memory: 512M
```

3. **Add health check endpoint to scraper** (add to services/hipages-scraper/src/scheduler.js):
```javascript
// Add after line 137 (before startScheduler())
const express = require('express');
const healthApp = express();
const HEALTH_PORT = process.env.HEALTH_PORT || 3000;

// Simple health check endpoint
healthApp.get('/health', (req, res) => {
  res.status(200).json({
    status: 'healthy',
    timestamp: new Date().toISOString(),
    uptime: process.uptime()
  });
});

// Start health check server (non-blocking)
healthApp.listen(HEALTH_PORT, () => {
  console.log(`[scheduler] Health check server listening on port ${HEALTH_PORT}`);
});
```

**What to avoid:**
- Don't set health check timeout too short (pagination may take 5+ minutes)
- Don't remove the existing docker-compose configuration for other services
- Don't forget to add the health check server to the scheduler (otherwise container will be marked unhealthy)

**Why:**
The enhanced scraper will take longer to run (5-10 minutes instead of 30 seconds) due to pagination. Docker health checks need to account for this longer runtime. Increased memory limits ensure the container doesn't get killed during large data extraction. The health check endpoint allows Docker to monitor scraper health.

**Verify:**
<automated>

</automated>

**Done:**
- Dockerfile updated with health check and timeout configuration
- docker-compose.yml updated with increased memory limits (1G)
- Health check endpoint added to scheduler.js
- Health check timeout increased to 30s (from default 10s)

## Troubleshooting

### Scraper stuck in loop
- Check logs: `docker logs hipages-scraper`
- Verify MAX_ITERATIONS limit in scraper.js
- Kill container: `docker-compose stop hipages-scraper`

- Log in to hipages.com.au and check for warnings

- Vacuum database: `VACUUM ANALYZE hipages_leads;`

## Threat Model

### Trust Boundaries

| Boundary | Description |
|----------|-------------|
| Docker host → Container | Trusted deployment environment |
| Container → hipages.com.au | Untrusted external API (rate limiting, TOS) |
| Container → Database | Trusted internal connection |

### STRIDE Threat Register

| Threat ID | Category | Component | Disposition | Mitigation Plan |
|-----------|----------|-----------|-------------|-----------------|
| T-05-10 | Denial of Service | Scraper overwhelming production database | mitigate | Docker resource limits (1G memory), database indexes |
| T-05-11 | Elevation of Privilege | Docker container escape | accept | Container runs in trusted environment, minimal attack surface |
| T-05-12 | Information Disclosure | Logs containing PII | mitigate | Logs only contain counts/timestamps, not lead data |
| T-05-13 | Tampering | Deployment rollback needed | mitigate | Tagged Docker images enable quick rollback (v1, v2, etc.) |
| T-05-14 | Repudiation | Audit trail for deployments | mitigate | Git commits, Docker image tags, database timestamps |
